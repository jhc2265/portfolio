Overview

다 못 해도 괜찮은 투두 리스트

enoughday는 부담 없는 투두 관리에 유머 한 스푼을 더한 웹앱입니다. 오늘 할 일을 적고 달성/실패를 체크하면, 실패한 항목에 대해 구름 마스코트가 대신 재치있는 핑계를 만들어줍니다.

"오늘은 여기까지"라는 태도로, 완벽하지 않아도 하루를 웃으며 마무리하도록 콘셉트·UX·화면 설계부터 기능 구현까지 직접 다뤘습니다.

Problem & Goal

왜 이렇게 만들었나

완벽한 생산성 도구가 아니라, 실패해도 가볍게 웃고 넘길 수 있는 투두를 목표로 방향을 먼저 정리했습니다.

Problem대부분의 투두 앱은 못 지키면 죄책감과 부담을 준다.
→
Goal실패한 일에 재치있는 ‘핑계’를 붙여 부담을 덜고 웃게 한다.
Problem할 일을 기기 간에 잃지 않고 이어서 보고 싶다.
→
GoalFirebase Auth·Firestore로 로그인·백업·실시간 동기화를 구현한다.
Problem배포·업데이트를 매번 수동으로 하면 번거롭고 실수가 난다.
→
GoalGitHub Actions CI로 커밋만으로 이중 배포가 자동화되게 한다.

Challenges

막혔던 부분 · 해결

PROBLEM‘실패해도 괜찮은’ 경험을 어떻게 만들까?

해결 → 못한 일에 위트있는 ‘핑계’를 생성하고, 말투 톤 5종 중에 골라 쓸 수 있게 설계해 부담을 덜었습니다.

PROBLEM할 일을 기기 간에 안전하게 동기화하고 싶다.

해결 → Firebase Auth·Firestore로 로그인·백업·실시간 동기화를 구현하고, 비로그인 미리보기까지 지원했습니다.

PROBLEM배포와 업데이트를 자동화한다.

해결 → GitHub Pages와 Firebase Hosting 이중 배포에 GitHub Actions CI를 구성해 커밋만으로 자동 배포되도록 했습니다.

Review

돌아보며

프론트엔드부터 백엔드(Firebase)·CI까지 1인 풀사이클을 경험한 프로젝트였습니다. 과정을 배운 점·아쉬운 점·개선 방향으로 정리했습니다.

배운 점

상태·인증·배포를 아우르는 풀사이클을 직접 경험하며, Firebase 연동과 CI 자동화 흐름을 익혔습니다.

아쉬운 점

핑계 생성이 정해진 문구 조합 기반이라, 더 다양하고 자연스러운 문장까지는 확장하지 못한 점이 아쉽습니다.

개선 방향

추후 통계·습관 리포트와 알림을 더하고, 핑계 생성을 더 풍부한 방식으로 발전시키고 싶습니다.

오늘 못한 일, 핑계는 enoughday가.
