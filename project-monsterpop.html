01Overview

30초면 한 판이 끝납니다

화면에 튀어나오는 몬스터를 탭 · 스와이프 · 더블탭 · 홀드로 처치하고, 30초 동안 콤보를 얼마나 이어가는지 겨루는 모바일 웹 게임입니다. 몬스터마다 필요한 조작이 달라서 반사신경만이 아니라 무엇을 어떻게 잡을지 판단하는 재미가 함께 걸립니다.

앱스토어를 거치지 않고 링크 하나로 접속하는 것이 전제였습니다. 설치·업데이트가 없는 웹으로 만들고, 첫 화면이 뜨는 속도를 프로젝트 내내 중요한 지표로 삼았습니다. 짧은 한 판이 랭킹·도감·미션·보스전으로 이어지도록 단기 플레이와 장기 성장의 흐름도 함께 설계했습니다.

02Problem & Goal

가볍게 들어와서, 다시 돌아오게

짧고 즉각적인 플레이의 장점은 살리되, 웹 게임에서 이탈을 만드는 세 가지 순간을 다시 찾고 싶은 경험으로 전환했습니다.

Problem 01
모바일 게임에는 설치라는 문턱이 있습니다. 한 번 해볼까 싶은 마음이 다운로드 화면에서 대부분 꺾입니다.
→
Goal 01
설치 없이 링크로 접속하고, 로그인 뒤 곧장 사냥할 수 있게 합니다. 운영 점검용 체험 모드는 서버 기록과 분리합니다.
Problem 02
짧은 게임은 한 번 하고 닫으면 그만입니다. 다시 열 이유가 없습니다.
→
Goal 02
랭킹·도감·레벨·일일 미션·보스 스트릭으로 내일 다시 올 이유를 만듭니다.
Problem 03
웹 게임은 첫 로딩이 길면 그대로 이탈합니다.
→
Goal 03
첫 화면에 필요한 것만 받아오도록 폰트와 이미지를 쪼갭니다.

03Design Guide

짧은 순간에도 읽히는 네온 헌팅 UI

30초 안에 판단과 조작이 반복되는 게임이라 장식보다 정보의 우선순위를 먼저 정했습니다. 어두운 전장 위에서 목표·상태·보상이 즉시 구분되도록 컬러, 타이포, 피드백 컴포넌트를 하나의 규칙으로 묶었습니다.

05Build

디자인에서 멈추지 않고 직접 만들었습니다

React + Vite

화면 13개를 라우팅으로 나누고 로그인 여부에 따라 접근을 막습니다. 상태는 Context 하나로 모아 진행도와 프로필을 한곳에서 다룹니다.

Supabase

인증, 7개 테이블, RLS 접근 정책을 구성했습니다. 점수와 커뮤니티뿐 아니라 성장·미션·보스·설정도 계정에 묶어 기기 간에 이어집니다.

Vercel

메인 브랜치에 올리면 그대로 배포됩니다. 링크 하나로 누구나 바로 플레이할 수 있습니다.

로컬 캐시 + 서버 동기화

읽기는 로컬에서 즉시, 쓰기는 캐시한 뒤 서버로 올립니다. 로그인 시 XP는 큰 값, 도감은 합집합, 설정은 최신 값처럼 데이터 성격에 맞춰 병합합니다.

06Challenges

막힌 곳에서 배운 것

조용히 사라진 기록

다른 기기로 로그인하면 레벨과 도감이 초기화돼 있었습니다. 원인은 코드가 쓰는 컬럼이 데이터베이스에 없었던 것 — 저장은 매번 실패했지만 화면은 이 기기에 남은 값을 대신 보여줘서 아무도 눈치채지 못했습니다.

진행도·미션·보스 기록·설정을 계정에 묶는 테이블을 따로 두고, 로그인할 때 두 기기의 값을 종류마다 다른 규칙으로 병합하도록 고쳤습니다. 진행도는 큰 쪽, 설정은 마지막에 저장한 쪽 — 줄어들면 안 되는 것과 최신이어야 하는 것이 다르기 때문입니다.

첫 화면의 70%가 폰트

Pretendard 한 파일이 2MB로 첫 화면 다운로드의 대부분을 차지했습니다. 글자를 빼는 서브셋은 닉네임에 어떤 한글이 올지 몰라 쓸 수 없었습니다.

대신 글자를 지우지 않고 범위로 쪼갰습니다. 앱에 실제로 등장하는 한글 700자를 한 조각으로 모으고 나머지는 따로 나눠, 브라우저가 화면에 나온 글자의 조각만 받아가게 했습니다. 첫 화면 폰트가 2,185KB → 363KB(−83%)가 됐습니다.

서버와 분리한 체험 모드

포트폴리오 확인과 운영 점검을 위해 전체 콘텐츠가 열린 체험 모드를 만들었습니다. Supabase 익명 로그인을 쓰면 방문자마다 실제 계정이 생겨 커뮤니티 권한이 붙고 랭킹과 MAU 데이터가 오염될 수 있습니다.

대신 서버 계정 없이 이 기기에서만 도는 신원을 사용하고, 점수 저장·랭킹 조회·커뮤니티 쓰기처럼 서버로 나가는 동작만 차단했습니다. 공개 가입 흐름과 분리된 숨은 진입으로 운영하면서도 게임·성장·미션·보스전은 온전히 검토할 수 있습니다.

—Review

배운 점

화면을 그리는 것과 서비스를 굴리는 일은 다르다는 걸 배웠습니다. 저장 실패를 감추는 폴백보다 오류를 드러내고 복구 경로를 설계하는 일이 운영에서는 더 중요했습니다.

아쉬운 점

실기기 테스트를 수동으로만 해서 기종별 조작감 차이를 데이터로 확인하지는 못했습니다.

개선 방향

친구와 겨루는 대전 모드와 시즌제 랭킹을 붙여, 혼자 기록을 세우는 게임에서 함께 하는 게임으로 넓히고 싶습니다.

디자인에서 멈추지 않고 직접 만들어 배포하고 운영해 본 첫 프로젝트입니다. 사용자에게 보이지 않는 곳에서 무엇이 무너질 수 있는지 알게 됐습니다.
